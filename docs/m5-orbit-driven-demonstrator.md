# M5 extension — orbit-driven mechanical tether demonstration

**Status:** physically consistent *prescribed-orbit* demonstration, **not** coupled spacecraft/orbit propagation or a mission flight-prediction model. The M5 milestone title stays **M5: Correct and Package Physical Tether Dynamics**.

## Why this case exists

The earlier `m5_mechanical_example.json` uses a 50 m, 100-segment, initially **bowed** and 1%-stretched cable with a fixed attachment and no gravity/current. That is deliberately retained as an independent axial relaxation/damping **regression** case. Its bow is an *initial condition*, not a prediction of environmental bending.

`m5_orbit_driven_500km.json` instead starts with a **straight, nominal-rest** 50 m cable. A prescribed circular orbit supplies attachment position, velocity and acceleration. Every node receives Earth-centered Newtonian gravity, which induces actual relative/tidal loading. Three paired scenarios distinguish gravity-driven effects, initial-angle/libration effects and an added controlled Lorentz load.

## Physics and reference frames

- A 500 km altitude circular orbit is generated by `CircularReferenceOrbit` with **`precess_raan=false`**, which is essential for consistent analytical two-body acceleration. The user can supply `inclination_deg` or request the first-order J2 SSO **inclination** via the string `"sso"`; this inclination does **not** cause the orbit to precess here. Epoch, real SSO nodal drift, J2 acceleration, atmosphere and orbital decay are **not** integrated.
- In Earth-centered ideal inertial Cartesian coordinates, the prescribed attachment obeys

  \[\mathbf a_a=-\mu\mathbf r_a/\|\mathbf r_a\|^3,\quad \mathbf g(\mathbf r_i)=-\mu\mathbf r_i/\|\mathbf r_i\|^3.\]

  The M5 solver propagates each node relative to the attachment using the existing physical tension-only chain; no orbital translation is integrated by this package.
- We apply a *constant translation* to the computational inertial origin equal to the Earth's-centered initial attachment position. This keeps node positions near tens of metres instead of \(6.9\times10^6\) m, greatly reducing floating-point spurious tension. Gravity adds the origin back before evaluating the Earth-centered field. The history NPZ stores the translation vector explicitly as `inertial_origin_Earth_centered_m`.
- The initial shape is

  \[\mathbf r_i(0)=\mathbf r_a(0)+u_iL(1+\epsilon)(\cos\theta\,\hat r_0+\sin\theta\,\hat t_0),\quad u_i=i/N.\]

  `straight_gravity` and `straight_lorentz` use \(\theta=0\), \(\epsilon=0\) by default. `tilted_gravity` uses a user-set initial rigid angular offset; **it is still straight at t=0**, only tilted. Velocity initialization includes co-rotation: \(\mathbf v_i=\mathbf v_a+\boldsymbol\omega_{\rm orb}\times(\mathbf r_i-\mathbf r_a)\). This is necessary to avoid an artificial transverse impulse from initially stationary inertial nodes.
- Plot output is in a time-dependent orthonormal local **radial/along-track/orbit-normal** frame (LVLH-like). Radial is positive away from Earth; along-track follows the prescribed orbital velocity; cross-track completes a right-handed triad. Tether deflection is most interpretable in these local axes.
- The model remains a **pin-attached tension-only cable**, with a prescribed bus attachment and **no dynamic response of the CubeSat**. `attachment_force_LVLH_N` is the constraint reaction *on the bus if it were allowed to respond*; there is no bus attitude or bus torque integration yet.

## Controlled electrodynamic loading case

The third run (`straight_lorentz`) calls an `electrodynamics` adapter to translate M4e **segment midpoint forces** into M5 **nodal forces**. Each half of a midpoint load goes to each endpoint, preserving net external force and moment about any reference. The anchored node's share participates in the attachment reaction.

For this controlled test only, the magnetic field is uniform in inertial space, directed along the reference **orbit normal**. Current is uniformly prescribed by `PrescribedConstantCurrent` and positive from spacecraft to tip. This is **not** WMM/IGRF, plasma current collection, or self-consistent CNT emission. A vectorized special case implements the same \(I\,d\boldsymbol\ell\times\mathbf B\) as M4e's general evaluator; it is independently tested against that evaluator. The general M4e path remains available for arbitrary field/current providers.

**Do not interpret electromagnetic bending here as proof of natural EDT deorbit or of a flight-achievable current.** M4e supplies only the *external* tether loading; the mechanical attachment reaction is calculated separately by M5.

## Running the comparisons

Install from the repository root:

```bash
python -m pip install -e ".[dev,tether,viz]"
python -m pytest tests/test_m5_orbit_driven.py -v
```

Run the 50 m, 100-segment examples:

```bash
python scripts/run_m5_orbit_driven_reference.py \
    configs/scenarios/m5_orbit_driven_500km.json \
    --output-dir results/m5_orbit_driven

python scripts/plot_m5_orbit_driven.py results/m5_orbit_driven
```

The output includes `summary.json` and, for each case in `straight_gravity`, `tilted_gravity`, `straight_lorentz`, a compressed `history.npz`, `history.csv`, and `shape_samples.csv`. The NPZ contains LVLH node histories, force reactions, node masses, segment tensions, tip angle and deviations from the instantaneous straight anchor-to-tip chord. Plots show evolving local shapes, libration, tip offset, tension and attachment forces.

The original bowed mechanical-only regression remains available separately:

```bash
python scripts/run_m5_mechanical_reference.py \
    configs/scenarios/m5_mechanical_example.json \
    --output-dir results/m5_curved_regression
```

For mesh refinement of the new orbital reference:

```bash
python scripts/run_m5_orbit_mesh_convergence.py \
    configs/scenarios/m5_orbit_driven_500km.json \
    --segments 25 50 100 200 \
    --output-dir results/m5_orbit_mesh
```

The finest mesh is an **internal numerical reference, not analytical truth**. Inspect tip and attachment-force time-history differences as well as final shape RMS differences. Mesh convergence in one soft illustrative cable is not validation of QSET hardware dynamics.

## Key limitations

- **Not an orbital simulator:** exact two-body circular reference with fixed plane; intentionally omits J2 precession, real time-dependent geomagnetism and orbital decay.
- **Not M6:** no spacecraft attitude or translation response to attachment reaction; no pin moment or flexible-bus co-simulation.
- **Not a high-fidelity tether:** no flexural rigidity, torsion, reel payout, contact or finite-thickness beam mechanics; material inputs are intentionally very soft and illustrative.
- **No fully validated circuit:** magnetic field and current are prescribed, with no solved CNT/plasma current closure; zero-current baseline is a verified control.
- **Energy caution:** `gravity_potential_J` and `total_mechanical_energy_J` in the generic M5 history are `NaN` for position-dependent gravity. The orbital runner intentionally does not claim isolated-system energy conservation. Distinguish local mechanical energy from the much larger inertial translational/orbital energy.
- **Input consistency:** initial tether positions and velocities include rotating-frame kinematics. Changing only the positions without matching velocities would introduce a nonphysical initial impulse.
